trie

Compact tries: StaticTrie<T>, an immutable map from Unicode code points to small integers that a program holds as static data, and its StaticTrieBuilder, which a table generator runs.

Bring it in with import trie.

  • StaticTrieBuilder: set values for code points and ranges, build the data, and write it with StaticTrieData.source as a const
  • StaticTrie<T>: reads a code point's value in O(1), with no allocation

Example

import trie;

main(): int {
    var builder = trie.StaticTrieBuilder(1);
    builder.set_range(0x4E00, 0x9FFF, 2);
    var widths = builder.build().reader<u8>();
    print(widths.get(0x4E2D));   # 2
    return 0;
}

hat_trie_map.pep

HatTrieMap<T>: a map from String keys to values, kept in key order, after Askitis and Sinha's HAT-trie.

Source: hat_trie_map.pep

DEFAULT_BURST_THRESHOLD

const DEFAULT_BURST_THRESHOLD: ulong = 16384

How many keys a container holds before HatTrieMap bursts it into a trie node, unless the trie is made with another threshold.

HatTrieMap

struct HatTrieMap<T>

A map from String keys to values of type T that keeps its keys in byte order (code point order, for valid UTF-8), after the HAT-trie of Askitis and Sinha: a trie whose leaves are array hash tables ("containers") that hold the rest of each key below them.

A container packs its keys into a few byte arrays, with no object per key, so the map takes much less memory than a HashMap<String, T> of the same keys. When a container holds more than the burst threshold of keys, it bursts: it becomes a trie node, and its keys move to a new container per first byte, without that byte. Lookups hash in one container after walking the trie, so they cost about as much as a hash map's; iterating in order sorts each container as it reaches it, and a prefix search (with_prefix) walks to the prefix and visits only what is under it.

Keys are compared as bytes. The map holds a reference to each value; it does not keep the key objects, only their bytes, so a key given to insert may be changed afterwards.

Type parameters

  • T — the value type

Example

import trie;

main(): int {
    var words = trie.HatTrieMap<int>();
    words["pepper"] = 1;
    words["pear"] = 2;
    words["apple"] = 3;
    for (var (word, n) in words.with_prefix("pe")) {
        print($"{word} {n}");   # pear 2, then pepper 1
    }
    return 0;
}

HatTrieSet

struct HatTrieSet

A set of Strings that keeps them in byte order (code point order, for valid UTF-8): a HatTrieMap whose values take no room, as Tessil's htrie_set is to htrie_map. It packs the strings into the containers' byte arrays, with no object per string, so it takes much less memory than a HashSet<String>, and finds every string with a prefix by walking to it (with_prefix).

Example

import trie;

main(): int {
    var words = trie.HatTrieSet();
    words.insert("pepper");
    words.insert("pear");
    words.insert("apple");
    for (var word in words.with_prefix("pe")) {
        print(word);   # pear, then pepper
    }
    return 0;
}

static_trie.pep

StaticTrie<T>: an immutable map from integer keys, 0 to MAX_KEY, to small integers, read from data that StaticTrieBuilder made. It is laid out as ICU's UCPTrie is, for Unicode code points, the use it is made for.

Source: static_trie.pep

MAX_KEY

const MAX_KEY: uint = 0x10FFFF

The largest key a StaticTrie holds: 0x10FFFF, the largest Unicode code point.

StaticTrie

[Value] struct StaticTrie<T>

An immutable trie that maps every key from 0 to MAX_KEY to a value of type T, in O(1) with no allocation. Made for dense keys whose values come in runs and repeat, such as the properties of Unicode code points.

Its data is one StringConstant that a StaticTrieBuilder wrote (StaticTrieData.source), so a const of a trie is static data: it costs only its bytes in the binary, no startup work, and nothing in a program that never reads it. A string literal holds only bytes up to 0x7F as static data (pep-lang/pepper#298), so each byte carries 7 bits, and an entry takes one or more of them, low bits first.

The layout follows ICU's UCPTrie:

  • a key below 0x80 (ASCII) reads its value at data entry key: one read;
  • one below fast_limit (0x10000, the BMP, or 0x1000 for a small trie) reads the start of its 64-value data block from a flat index: two reads;
  • one from high_start up has high_value: no read;
  • the rest read an index-1 entry for their 1024 keys, an index-2 entry for their 16, then the value: three reads.

Type parameters

  • T — the value type: u8, u16 or uint, or any integer type the trie's values fit in

Example

import trie;

# Written by StaticTrieData.source(), usually in a build script.
const WIDTHS = trie.StaticTrie<u8>("...", 1, 2, 4096, 918528, 1, 1172);

main(): int {
    print(WIDTHS.get(0x4E2D));   # 2
    return 0;
}

enum StaticTrieKind

Which layout StaticTrieBuilder.build writes, as ICU's UCPTRIE_TYPE_FAST and UCPTRIE_TYPE_SMALL.

Cases

Fast

Fast

A flat index below 0x10000 (the BMP, for code points): two reads there, and a larger index (1024 entries).

Small

Small

A flat index only below 0x1000: two reads there, three above, and a smaller index.

StaticTrieBuilder

struct StaticTrieBuilder

Builds a StaticTrie: set values for keys and ranges of keys, then build it.

Holds a value for each of the 0x110000 keys (4.4 MB), so it is for build scripts and generators, not for the programs that read the trie. build merges equal data blocks and equal index blocks, and overlaps each new block with the end of the one before where they agree, as ICU's builder does.

Example

import trie;

var builder = trie.StaticTrieBuilder(1);
builder.set_range(0x1100, 0x115F, 2);
builder.set(0x200B, 0);
var data = builder.build();
var widths = data.reader<u8>();      # widths.get(0x1100) == 2
print(data.source("u8"));             # trie.StaticTrie<u8>("...", ...)

reader

reader<T>(): StaticTrie<T>

Returns a trie that reads these bytes at run time, for data built in the same program (a test, or a table built at startup). It copies the bytes into memory that is never freed, as a string literal's bytes are not, so the trie outlives this object: make a reader once per table, not per lookup. A generator writes source() instead.

Type parameters

Returns

source

source(value_type: String): String

Returns the Pepper expression that makes this trie from literals, for a generator to write after const NAME = ; the program that reads it then holds the bytes as static data. It names the type as trie.StaticTrie, so that file imports trie.

The string is one line. Bytes from space to ~ are written as they are (with " and \ escaped), the rest as \x escapes.

Parameters

Returns

  • the expression

Example
