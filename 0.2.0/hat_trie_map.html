Source: hat_trie_map.pep

DEFAULT_BURST_THRESHOLD

const DEFAULT_BURST_THRESHOLD: ulong = 16384

How many keys a container holds before HatTrieMap bursts it into a trie node, unless the trie is made with another threshold.

HatTrieMap

struct HatTrieMap<T>

A map from String keys to values of type T that keeps its keys in byte order (code point order, for valid UTF-8), after the HAT-trie of Askitis and Sinha: a trie whose leaves are array hash tables ("containers") that hold the rest of each key below them.

A container packs its keys into a few byte arrays, with no object per key, so the map takes much less memory than a HashMap<String, T> of the same keys. When a container holds more than the burst threshold of keys, it bursts: it becomes a trie node, and its keys move to a new container per first byte, without that byte. Lookups hash in one container after walking the trie, so they cost about as much as a hash map's; iterating in order sorts each container as it reaches it, and a prefix search (with_prefix) walks to the prefix and visits only what is under it.

Keys are compared as bytes. The map holds a reference to each value; it does not keep the key objects, only their bytes, so a key given to insert may be changed afterwards.

Type parameters

  • T — the value type

Example

import trie;

main(): int {
    var words = trie.HatTrieMap<int>();
    words["pepper"] = 1;
    words["pear"] = 2;
    words["apple"] = 3;
    for (var (word, n) in words.with_prefix("pe")) {
        print($"{word} {n}");   # pear 2, then pepper 1
    }
    return 0;
}

Constructor

HatTrieMap()

construct(burst_threshold: ulong = DEFAULT_BURST_THRESHOLD)

Makes an empty trie.

A lower burst_threshold makes more, smaller containers: in-order and prefix iteration sort less at a time, at the cost of more trie nodes (2 KB each). Tessil's hat-trie suggests 1024 or less when iteration matters more than lookups.

Parameters

  • burst_threshold — how many keys a container holds before it bursts; at least 4

Panics

  • if burst_threshold is below 4

iterate

iterate(): HatTrieMapIterator<T>

Returns an iterator over the entries as (key, value) tuples, in key order; for (var (key, value) in trie) drives it.

Each container is sorted when the iterator reaches it, which costs O(n log n) for its n keys. Adding or removing a key makes the iterator's next next() panic.

Returns

  • an iterator positioned before the first entry

with_prefix

with_prefix(prefix: String): HatTrieMapIterator<T>

Returns an iterator over the entries whose key starts with prefix, in key order. It walks the trie to prefix, so it visits only the keys under it, plus the rest of one container when prefix ends inside one.

Parameters

  • prefix — the bytes every key visited starts with; "" visits all

Returns

  • an iterator positioned before the first such entry

Example

var n = 0;
for (var (key, value) in trie.with_prefix("app")) {
    n += 1;
}

HatTrieMapIterator

struct HatTrieMapIterator<T>

An Iterator<(String, T)> over a HatTrieMap's entries in key order; returned by HatTrieMap.iterate and HatTrieMap.with_prefix.

It holds a reference to the trie and fails fast: adding or removing a key after it was made makes its next next() or current() panic.

Type parameters

  • T — the trie's value type

Constructor

HatTrieMapIterator()

construct(trie: HatTrieMap<T>, start: _HatNode<T>, path: u8[], prefix: String, depth: ulong)

Makes an iterator over the keys under start, which path leads to, that start with prefix's bytes from depth on. HatTrieMap.iterate and HatTrieMap.with_prefix call it.

Parameters

  • trie — the trie
  • start — the node to start at; null for no entries
  • path — the bytes that lead to start
  • prefix — the prefix searched for
  • depth — how many of prefix's bytes path holds
